# Adaptive-Labyrinth-Escapist

The Adaptive-Labyrinth-Escapist (ALE) is a platform upon which any number of search algorithms can be implemented, visualized, and have their performances measured.

## Installation Guide

1. To get started, ensure that you have Python version 3.10 or later installed. 

2. Next, obtain a copy of the repository.

    ```
    git clone https://github.iu.edu/ermili/Adaptive-Labyrinth-Escapist.git
    ```
    > e.g. clone the repository with git

3. The only dependency for this project is Pygame, which can be installed via `pip`.

    ```
    pip install pygame
    ```

4. That's it! 

## Usage Guide

```
python game.py
```
> To run the GUI 

```
python main.py
```
> To run the non-GUI sandbox

```
python collect_data.py
```
> To record data about algorithm performance in `collected_data.csv`

## Extension Guide

So you want to implement more algorithms eh? 
> Yes king

The following are the files you would need to familiarize yourself with and update:

1. `graph.py`

    It is likely unnecessary to understand all of the implementation details of the `Graph` class. 
    
    What is important to know is:
    - all the edges and vertices of a graph are representated by coordinates (tuples of ints) that point to locations in a 2D matrix (list of lists of ints) 
    - a graph has specified `start` and `goal` vertices that are randomly generated
    - removing an edge from the graph corresponds to adding a wall to the maze 
    - adding an edge to the graph corresponds to removing a wall from the maze  
    - diagonal movement (i.e. diagonal edges) can be enabled/disabled during initialization 
    - the purposes and the availability of all the functions

    Since the initial goal of this project was to try D* Lite in a dynamic environment, trying a different graph implementation requires the modification of all uses of the `Graph` class, which basically entails starting from scratch.  

2. `search_algorithm.py`

    The `SearchAlgorithm` class outlines the three methods a search algorithm must implement. 
    - `ComputePath()` : Computes a path from `G.start` to `G.goal` which should be retraceable by `PickSuccessor()`.
    - `PickSuccessor()` : Returns the next vertex along the path from `G.start` to `G.goal`.
    - `AdaptToChanges(changed_edges)` : Recomputes the path from `G.start` to `G.goal` after potentially making adjustments based on the edges of the graph that changed (i.e. were added or removed).
    
    Ensure that the classes for your new search algorithms extend `SearchAlgorithm` and that their constructors receive a `Graph` as an input. 
    
    ```python
    from typing import Tuple, List
    from graph import Graph
    from search_algorithm import SearchAlgorithm

    class DFS(SearchAlgorithm):
        def __init__(self, G : Graph):
            self.G = G
            ...
        
        def ComputePath(self) -> None:
            ...
        
        def PickSuccessor(self) -> None:
            ...
            return succesor

        def AdaptToChanges(self, changed_edges : List[Tuple[int, int]]) -> None:
            ...
    ```
    > e.g. class for Depth First Search in `dfs.py`

3. `algorithms.py`
    
    For each of your new your new algorithms, import them and add a mapping from their name to their class

    ```python
    ...
    from dfs import DFS

    # TODO add mappings from algorithm names to their classes here
    algorithms = {'d* lite':DStarLite, 'bfs':BFS, 'dfs':DFS}
    ```
    > e.g. import the `DFS` class from `dfs.py` and add the mapping `'dfs':DFS` to `algorithms`

4. `main.py` and `game.py`

    Select the name of algorithm you wish to experiment with or visualize

    ```python
    # TODO change algorithm name here
    algorithm_name = 'd* lite'
    ```

5. `collect_data.py`
    
    Ensure that you are only gathering data about algorithms you are interested in

    ```python
    # TODO add/remove algorithm names from this list
    algorithm_names = list(algorithms.keys())
    ```

## Table of Contents

### Graph and Search Algorithms

- `graph.py` provides an implementation of a randomly generated maze that can be randomly updated. This graph is used by all the search algorithms.
- `previous_maze.txt` stores the information needed to recreate the maze that was previously generated by running `main.py`.
- `maze_recreation_info_example.txt` specifies the information needed to create a maze via a text input file. 
- `search_algorithm.py` contains an abstract class that establishes the methods required to implement a search algorithm. 
- `algorithms.py` contains mappings from search algorithm names to their respective classes. This furthers the goal of making ALE extensible as it reduces the amount of code to update in order to integrate additional search algorithms.
- `dstarlite.py` provides an implementation of the D* Lite algorithm from the paper [**D* Lite**](https://idm-lab.org/bib/abstracts/papers/aaai02b.pdf) written by Sven Koenig and Maxim Likhachev.
- `entry.py` provides the implementation of the special entries used in the priority queue in `dstarlite.py`.
- `tests.py` is supposedly where unit tests for D* Lite should go.
- `bfs.py` provides an implementation of Breath First Search.

### Visualization and Experimentation

- `game.py` provides an Among Us themed GUI to visualize search algorithms and make changes to mazes in the midst of searches.   
- `assets` is a directory containing all the images and audio necessary for the GUI.
- `main.py` is another sandbox, primarily used before the development before of the GUI, that is useful for experimenting with the algorithms.

### Performance Measurement

- `collect_data.py` records execution times and path lengths of the algorithms specified in the file on mazes that allow as well as disallow diagonal movement. 
- `collected_data.csv` stores the data generated by `collect_data.py`

### Misc.

- `.gitignore` instructs git to ignore `__pycache__` directories.
